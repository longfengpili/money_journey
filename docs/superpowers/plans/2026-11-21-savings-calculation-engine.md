# 独立储蓄计算引擎实施计划

> 执行要求：使用 superpowers:executing-plans 在当前会话逐项实施，测试先复现问题，再实现与核验。

**目标**：计算引擎可脱离 Django 运行，相同输入可重复计算，页面兼容现有结果。

**架构**：savings_calculator.inputs 使用现有 ORM 口径准备纯数据。SavingsCalculator 只处理日期、配置和 Decimal 现金流。视图保持会话与结果字段契约。

**技术栈**：现有 Python、Decimal、Django、MySQL，无新运行依赖。

**设计依据**：[已批准设计](../specs/2026-11-21-savings-calculation-engine.md)。

## 全局约束

- 保留年龄区间首个匹配、区间外零收入及最近支出、80 岁停止、年度支出、整万元及三年单利转存。
- 保留月度结果、摘要和会话字段，内部使用 Decimal。
- 登录模式使用全家 ACTIVE 资产，活期仅汇总 CURRENT，初始存款沿用开始日期和到期日期分组及原公式。
- 游客使用表单活期金额，从最早年龄段对应年份 1 月开始。
- 引擎不得读取数据库、登录状态和系统当前时间。
- 文档及新增注释使用中文，Python 遵循 PEP 8。

## 重点核验

1. 同实例连续计算或先算部分月份再全量计算，存款队列均恢复初始状态。
2. 初始资产于首月到期、跨年度支出以及第 36 个月到期只计算一次。
3. 初始资产缺少开始日期时给出明确错误，已到期资产沿用原移除规则。
4. 未登录时零数据库查询，登录时全家资产输入来自同一条分组查询。
5. 80 岁边界产生空结果，结果页没有会话或结果为空均正确重定向。

## 实施判断

- 本次确认覆盖设计与实施，沿用已选当前会话执行方式。
- 用同一条分组查询附加 CURRENT 条件汇总，替代分散的两次查询，确保一次取数中得到活期和初始存款。存款金额与到期金额仍沿用旧聚合公式。
- 起始日期在输入准备层按 Asia/Shanghai 本地日期决定，引擎统一使用该月第一天，不访问系统时钟。
- 保留原首次计算及摘要口径，达到 80 岁时直接终止月份循环。
- 沿用现有 Decimal 递归转换函数处理会话结果，保持金额浮点展示及结果字段，避免重复维护手工字段列表。
- 历史未到期存款缺少开始日期时给出明确错误，保持原有本金与利息口径，已过期存款继续按旧规则移除。
- 跳过已勾选删除的年龄段，修正结果缺失重定向，均对应当前表单与结果入口的已有语义。
