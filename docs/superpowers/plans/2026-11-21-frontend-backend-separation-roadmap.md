# Money Journey 前后端分离与组件化重构规划

> 状态：用户已授权连续实施阶段 0–7，每阶段提交；进度见 2026-11-21-component-frontend-progress.md。
> 后续执行：每个阶段分别形成设计与实施计划，使用 superpowers:executing-plans 按阶段执行、验证和独立审查；用户后续消息已明确授权连续实施所有阶段，无需逐项确认。

**目标**：以组件化前端统一视觉、提升家庭资金管理操作体验，复用现有 Django 业务能力，逐步替换模板页面。

**架构**：同一仓库维护 frontend 与 Django，前端通过 /api/v1/ 调用业务接口；生产经同一入口发布，前端静态文件与 API 按路径分发。保留 MySQL、Django Admin 及已重构的业务模块，逐页验收后切换入口。

**推荐技术栈**：React 19、TypeScript、Vite、Tailwind CSS v4、BoardUI；Django 与 Django REST framework 提供 API。版本在基础阶段按实际 Python/Node 环境兼容性验证并锁定。

**依据**：当前 accounts、funds、analytics、savings_calculator 实现，以及用户已确认的单家庭、账号即成员和资产编辑权限。

## 已知基础与规划边界

- 当前页面使用 Django 模板、Bootstrap、Chart.js、部分 DataTables，没有现成 React 工程或完整 JSON 业务接口。
- 已有 accounts.permissions、FundRecordForm、import_fund_csv、refresh_daily_snapshots、analytics.queries、prepare_calculation_inputs 和纯计算引擎可复用。
- 最近一次已验证的后端基线为 MySQL 84 项测试；这是现有能力基线，新前端不能只靠这些测试验收。
- 现有代码确认结果页具有 CSV 导出；README 中其他格式的描述不作为已实现能力的证据，阶段 0 逐项核对可访问功能。
- 仍只管理一个家庭；成员共享查看，普通成员修改本人资产，家庭管理员修改所有资产及审批成员。
- 本轮不新增多家庭、AI 功能、支付、独立移动应用或新的财务计算规则。
- 当前工作目录实施，不创建 worktree；按用户后续授权逐阶段验证、提交并连续实施，默认入口切换已验收；不自动推送或删除旧文件。

## 路线选择

| 方案 | 收益 | 代价 | 判断 |
| --- | --- | --- | --- |
| 原模板统一样式 | 改造快，部署简单 | React 组件难以直接复用，复杂交互仍分散 | 适合仅改善视觉 |
| React 前端与 Django API，逐页迁移 | 组件可复用，交互和接口逐步统一，现有业务可沿用 | 新增接口、构建与前端测试 | 本规划推荐 |
| 全量重写并同时切换 | 一次统一所有页面 | 权限、校验、计算与部署同时变化，难以定位回归 | 不采用 |

## 视觉与组件规范

- BoardUI 作为主要基础组件来源，先使用免费且许可明确的组件；Pro 模板和组件单独列清单，不预设购买，也不自动付费。
- 图表首期复用现有 Chart.js 数据表达与计算，使用 React 适配统一生命周期和样式；BoardUI Pro 图表可另行评估，避免用付费图表阻塞第一阶段。
- 统一字体与中文回退、字号、间距、颜色、圆角、阴影、容器宽度与响应式规则。
- 同时定义常态、悬停、焦点、禁用、加载、成功、错误、空数据与未授权状态。
- 业务组件重点为 MoneyText、StatusBadge、OwnerSelect、FilterBar、AssetTable、AssetForm、StatCard、TrendChart 和 ImportResult。
- 金额表格右对齐、保留两位小数和千位分隔；不能只依赖颜色区分状态。
- 桌面支持完整表格和导航；手机采用折叠菜单、优先列或记录卡片，并保持编辑、筛选和导入可操作。
- 错误紧邻字段显示并保留输入；成功反馈与数据更新一致；加载状态避免整页闪动。
- 交互按钮要有键盘焦点，弹窗管理焦点和返回位置，动效尊重减少动画设置。

## 接口与业务约束

### 身份与权限

- 使用同域 Session + CSRF；开发时由 Vite 代理 API，生产同域入口，先避免跨域认证复杂度。
- 新登录接口必须显式校验匿名登录请求的 CSRF，不能依赖 DRF 的已登录会话 CSRF 检查代替登录保护。
- 生产配置启用了 CSRF_COOKIE_HTTPONLY，因此前端通过受控的初始化响应获取可用 CSRF token，登录轮换后重新获取，不从 document.cookie 读取。
- API 每次依据当前账号停用、审批和家庭角色判定权限；游客仅访问明确的演示和计算入口。
- 前端根据后端返回的操作能力控制按钮，后端仍独立检查每次请求，不信任前端传入的角色、创建者或权限字段。
- 登出后清除前端缓存和计算展示；切换账号不复用前一个账号的接口缓存。登录前后计算结果沿用现有会话边界，迁移前明确兼容规则。

### 数据与错误

- API 金额使用十进制字符串，后端 Decimal 负责计算；前端表格使用字符串安全格式化，仅图表坐标边界转 number，不用图表数值重新合计资金。
- 日期使用 YYYY-MM-DD，业务日为 Asia/Shanghai；时间戳包含时区，前端明确格式化。
- 成员、资产使用稳定 ID 标识，姓名只作展示；空关联历史记录明确展示待核对，不能用同名推测归属。
- 新成员选择器按 ID 筛选；现有用户名部分匹配行为保留兼容入口，接口契约说明两者区别。
- 列表分页建议默认 50、上限 100，稳定排序并以 ID 作并列排序；筛选状态写入 URL，翻页不会丢失筛选，改变筛选重置页码。
- API 错误明确区分字段错误、未登录、无权限、CSRF 失败与系统异常；返回稳定错误码和中文可展示信息，不返回堆栈或数据库错误。
- 资产写入复用当前表单校验及权限规则。API 对 ID、JSON、PATCH 的适配集中实现；若需抽出与 HTML 无关的校验模块，旧页面同步复用，不维护两套规则。
- 写请求结果不明时不自动重试；刷新快照沿用当天原位更新和全家原子提交。CSV 合法行统一提交、非法行报告的现有语义保持。
- 统计和计算继续在后端完成；列表分页不能导致全家统计仅包含当前页。

## 候选接口与职责

以下为接口规划，具体请求、响应和错误格式在阶段 1 固化，尚未创建。

| 接口范围 | 候选路径 | 职责 |
| --- | --- | --- |
| 身份上下文 | GET /api/v1/auth/context/ | 当前用户、审批状态、可执行操作及 CSRF 初始化 |
| 登录登出 | POST /api/v1/auth/login/、logout/ | Session 认证和明确错误反馈 |
| 统计 | GET /api/v1/analytics/summary/、trend/ | 复用统一汇总与历史趋势查询 |
| 枚举与成员 | GET /api/v1/funds/options/、/api/v1/members/ | 银行、类别、状态及授权可选所有者 |
| 资产 | GET/POST /api/v1/funds/，GET/PATCH /api/v1/funds/{id}/ | 分页读取、创建、编辑；不新增删除入口 |
| CSV | POST /api/v1/funds/import/，GET /api/v1/funds/import-template/ | 复用导入和错误行报告 |
| 快照 | POST /api/v1/snapshots/refresh/ | 家庭管理员刷新当天全家快照 |
| 计算器 | POST /api/v1/calculator/calculate/ | 复用输入准备和纯计算引擎，返回结果及摘要 |
| 注册审批 | POST /api/v1/auth/register/，GET/POST /api/v1/approvals/... | 注册校验、待批准列表和批准操作 |
| 成员创建 | POST /api/v1/members/ | 管理员创建不可登录的家庭成员 |

## 重点验证与通过标准

1. **数据一致**：金额、条数、归属、状态、快照与计算结果保持一致；大额两位小数、零金额和历史空关联有样例。
2. **权限一致**：游客、未批准、停用、普通成员、家庭管理员和系统维护账号分别验证 API 与页面；伪造所有者及角色字段无效。
3. **写入安全**：资产字段错误保留输入，CSV 写入失败整体回滚，快照并发保持唯一；未明确成功的操作不显示成功。
4. **状态完整**：空结果、网络失败、会话过期、CSRF 轮换、浏览器刷新、回退及切换账号均可恢复到明确状态。
5. **视觉可用**：代表性桌面和手机宽度下完成筛选、编辑、导入、计算；键盘操作、焦点和错误提示可用。
6. **验证层次**：保留 Django/MySQL 全套回归，新增 API 契约测试、关键组件测试与浏览器端到端流程；图表脚本模拟不能代替浏览器视觉验收。
7. **部署可回退**：新旧页面短期兼容同一数据库，API 优先采用增量方式；前端包与后端接口作为兼容组合发布，入口切换回退无需恢复业务数据。

每阶段只在上述相关检查通过后进入下一阶段；不以截图或能打开页面作为功能完成依据。
