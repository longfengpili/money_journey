# 资产统计与图表查询重构实施计划

> 执行要求：使用 superpowers:executing-plans 在当前会话实施，先观察测试失败再实现，最后进行独立审查。

**目标**：统一实时资产统计与历史趋势查询，修复账号改名筛选和图表 JSON 传递。

**架构**：analytics.queries 负责标准化筛选、单次资产分组汇总与按日期快照趋势；视图只负责游客分流和组织页面上下文。两个模板通过 json_script 接收图表数据。

**技术栈**：现有 Django、Decimal、MySQL、Chart.js，无新增依赖或迁移。

**设计依据**：[已确认设计](../specs/2026-11-21-asset-analytics-design.md)。

## 全局约束

- 当前目录执行，不创建 worktree；本轮不自动提交、合并或推送。
- 全家共享查看、默认 ACTIVE、显式空状态代表全部，保留所有者部分匹配。
- 已关联记录按当前账号归属；空关联历史记录使用原 owner 文本，不猜测归属。
- 趋势仅跟随所有者筛选，页面说明实时筛选与每日 ACTIVE 快照的区别。
- Decimal 用于计算和表格；图表展示边界转为数值，使用 json_script 传递。
- 保留游客模式与现有页面布局，仅验证独立测试数据库。

## 重点核验

1. 同显示姓名的成员必须按账号区分，历史空关联 owner 与账号同名时也不合并统计行。
2. 改名后新名称查询命中已关联旧快照，旧 owner 文本不会错误命中另一已关联账号。
3. 缺失状态参数与显式空状态的行为不同；空数据和零金额保持可用。
4. 显示名含引号、换行、脚本结束标签时保持文本语义，图表初始化不执行成员内容。
5. 无快照及有快照页面均无不存在控件引起的 JavaScript 错误。
