# 当天资金快照刷新实施计划

> 执行要求：使用 superpowers:executing-plans 在当前会话按任务实施，先观察回归失败，再实现并核验。

**目标**：管理员原子刷新当天全家快照，重复及并发调用保持用户日唯一，旧记录检查保留数据。

**架构**：funds.snapshots 集中权限、成员锁定、单次资产分组查询和批量写入，FundSnapshot 唯一约束保证用户日唯一。原创建路由调用刷新服务，后台查看计算结果，历史检查仅报告候选记录。

**技术栈**：现有 Django、Decimal、MySQL，复用当前目录与独立测试容器。

**设计依据**：[已确认设计](../specs/2026-11-21-daily-snapshot-refresh.md)。

## 全局约束

- 同一天更新已有用户快照，补齐缺失成员，历史日期保留。
- 家庭管理员刷新，成员共享查看。
- ACTIVE 资产纳入汇总，零资产成员生成零值记录，空归属明确报错。
- 全部成员统一事务，失败整体回滚，按固定成员顺序锁定并配合数据库唯一约束。
- 金额使用 Decimal，汇总 JSON 写入两位小数字符串。
- 旧记录检查仅筛选三年前最后更新的 WITHDRAWN 或 ROLLED_OVER 候选，保留记录。

## 重点核验

1. 刷新时新增、改金额、转移归属和改变状态均反映到当天记录。
2. 旧当天部分记录补齐，中途失败已更新值及新增行均回滚。
3. MySQL 并发刷新没有重复行、死锁或部分提交。
4. 历史重复记录迁移前明确报告，空归属数据不被猜测合并。
5. 用户名最长 150 字符的无资产成员可生成快照，日期按本地业务日。
