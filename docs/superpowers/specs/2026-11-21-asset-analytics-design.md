# 资产统计与图表查询重构设计

## 目标与范围

用户已确认抽出统一统计模块，集中处理筛选、汇总与趋势查询，并通过标准 JSON 向图表传递数据。系统继续只记录一个家庭，登录成员共享查看家庭数据。本次沿用当前工作目录，不创建 worktree。

保持现有页面布局、路由、默认 ACTIVE 统计及游客演示模式；不修改资产、快照、账号数据，不新增数据库迁移，不扩展到期提醒或储蓄计算。

## 现状与问题

- analytics/views.py 同时处理请求参数、数据库查询、维度汇总、展示名称和图表数组；dashboard 和 charts 分别维护银行、类别汇总。
- 实时资产通过关联账号查询归属，历史趋势通过快照 owner 文本筛选，账号改名后当前名称无法命中旧快照。
- 两个模板使用 safe 将 Python 列表直接拼入 JavaScript，成员显示名称包含引号或脚本结束标签时，可能破坏脚本或页面。
- 仪表板趋势脚本绑定不存在的 ownerSelect 元素，产生 JavaScript 错误。

## 方案比较

1. **统一查询模块，保留现有页面（已选择）**：将筛选和统计集中在 analytics 的独立模块，视图负责游客分流、调用与渲染。改动集中，两个页面共用统计规则，方便直接验证。
2. **仅抽取重复辅助函数**：文件变化较少，但筛选、历史趋势和图表数据组织仍分散在视图，难以保证后续口径一致。
3. **新增统计 HTTP 接口并改造前端加载**：支持独立刷新，但增加接口、请求状态和权限入口，超出本次现有页面重构范围。

## 查询与展示规则

- 仪表板保留 owner、bank、category、savings_status 查询参数。未传状态参数默认 ACTIVE，显式传空值表示全部状态。
- 所有者筛选保留现有用户名部分匹配；已关联记录依据账号当前用户名，空关联历史记录依据原 owner 文本。银行、类别、状态保持代码精确匹配。
- 实时汇总以账号 ID 区分成员，显示姓名优先 first_name，再使用用户名；空关联历史记录保留原文本，缺失名称展示“待核对所有者”。同名成员不合并。
- 总金额、记录数量以及成员、银行、类别、状态汇总来自同一份已筛选资产汇总结果。金额计算保持 Decimal，空结果金额为零、数量为零、各维度为空列表。
- 图表页继续显示全家 ACTIVE 分布，复用同一统计规则。本轮不为图表页新增筛选交互。
- 历史趋势只跟随所有者筛选，继续按日期合计 total_amount。有关联账号的快照按账号当前用户名筛选，空关联快照按历史 owner 文本筛选；不通过同名文本猜测归属，不重写历史名称。
- 银行、类别和状态筛选仅作用于实时资产统计。现有快照无法完整还原这些维度的交叉历史，因此趋势区增加简短说明，明确趋势展示每日 ACTIVE 快照、仅跟随所有者筛选。
- 快照日期按日展示；无快照时隐藏趋势图。保留旧快照 JSON 数值及字符串格式，趋势直接读取 total_amount。

## 模块与数据传递

- 新增 analytics 查询模块，将请求筛选标准化、资产汇总及快照趋势封装在少量明确函数中。具体命名与返回结构由实施阶段决定，避免为未来需求增加通用框架。
- 资产通过一次按成员、银行、类别、状态分组的金额和数量查询生成各维度统计；成员筛选选项独立读取全家资产的所有者，保持现有选项范围。
- 查询显式清除模型默认排序，汇总结果按金额降序并增加稳定的并列排序。
- 表格金额保留 Decimal；图表的数据集中组织后使用 Django json_script 输出，由 JavaScript JSON.parse 读取。仅在图表展示边界转为 JavaScript 数值，不宣称浏览器浮点数具有 Decimal 精度。
- 游客继续使用既有演示数据，同样采用 JSON 传递；本轮不重新设计演示数据。
- 移除绑定不存在 ownerSelect 的失效脚本；成员筛选仍使用现有筛选表单。

## 验收与验证

1. 仪表板和图表页在相同 ACTIVE 范围下，成员、银行、类别合计与总金额一致。
2. 覆盖默认状态、全部状态、组合筛选、空数据、零金额及两位小数，确保金额计算不提前转换为浮点数。
3. 账号改名后，通过新用户名能查询该账号此前生成的快照；空关联旧快照保留文本筛选，同名其他账号不被误并入。
4. 覆盖同名成员、姓名缺失、旧 owner 文本和稳定排序。
5. 显示名称含引号、换行和脚本标签时，JSON 可还原原值且不会形成可执行脚本；两个模板不再通过 safe 插入图表数组。
6. 游客页面、登录成员共享查看、历史趋势及原有回归正常。
7. 运行 SQLite 与独立 MySQL 测试、真实 HTTP 检查，并验证图表脚本初始化和数据读取。原业务库保持原样。
