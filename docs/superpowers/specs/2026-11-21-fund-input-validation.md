# 资金录入与 CSV 校验重构设计

## 目标

将页面新增、页面编辑、CSV 导入的字段校验集中到 Django 表单，统一金额精度和日期处理，继续使用已确认的家庭资产权限规则。

## 已检查的差异

- 模型和页面允许金额为零，CSV 当前要求金额大于零，用户已确认统一允许零金额。
- 页面仅检查少量必填字段，保存模型不会自动调用完整校验，选择值和金额精度缺少一致的服务端保障。
- CSV 使用 float 解析金额和利率，随后交给 DecimalField 保存，可能产生精度和舍入差异。
- 页面会将非法存期静默改为空，CSV 会报错。CSV 会将非法储蓄状态静默改为 ACTIVE。
- CSV 日期支持 YYYY-MM-DD、YYYY/MM/DD、YYYYMMDD，页面仅处理 YYYY-MM-DD。
- 页面保存依赖模型 save 计算衍生字段，CSV bulk_create 绕过 save，自行计算 due_month 和 start_date。
- 编辑清空到期日后，旧 due_month 仍可能保留。

## 推荐方案

复用 Django ModelForm 作为字段校验入口，CSV 模块负责列名、中文枚举、日期格式和错误行号的适配。所有者解析继续复用 funds.permissions，写入人继续由服务端指定。

页面和 CSV 共用字段规则，使金额、利率、存期和日期的合法性集中维护。相较于继续在三个视图中抽取零散解析函数，这个方案也能复用模型的字段精度与选择项校验。

## 字段规则提案

| 字段 | 统一行为 |
| --- | --- |
| 金额 | 使用 Decimal，最多 15 位数字、2 位小数，拒绝 NaN、Infinity、超限精度及负数，允许零金额 |
| 利率 | 可空，使用 Decimal，最多 5 位数字、2 位小数，非负 |
| 存期 | 可空，填写时为正整数，延续页面 min=1 的含义 |
| 银行、类别、储蓄状态 | 使用模型定义的有效选项，非法值明确报错，状态省略或留空时为 ACTIVE |
| 到期日 | 可空，接受现有三种日期格式，保存为 date |
| 所有者 | 沿用现有账号关联和权限解析，拒绝普通成员指定他人 |
| 开始日期 | CSV 继续支持显式输入，省略时沿用现有按 365 天乘存期倒推的规则 |
| 到期月份 | 由到期日派生，清空到期日时同步清空 |

## 页面交互

沿用当前路由、表单字段名和页面结构。校验失败时在原页面显示字段错误并保留输入，成功后沿用原有重定向与提示。管理员省略所有者时保留原归属，历史未关联记录仍须明确指定所有者。

## CSV 导入

- 继续支持 UTF-8 与 UTF-8 BOM、现有英文代码及中文选项、可选所有者、现有日期格式。
- 保留 10MB、10,000 行限制及 100 条一批的写入方式。
- 合法行可以导入，非法行显示对应字段和行号，校验错误不会阻断其他合法行。
- 文件超限、编码错误和缺少必需列时整份不写入。
- 所有已校验的合法行在同一事务中写入，数据库写入异常时整体回滚并报告失败。
- 使用同一处衍生字段计算逻辑供普通保存和批量导入调用。
- 模板下载的示例所有者留空，说明内容与统一规则同步。

## 实施范围

新增 funds/forms.py 与 funds/importers.py。修改资金视图、模型衍生字段计算、现有录入及导入模板，增加入口回归测试和必要说明。

本阶段沿用现有数据表结构及迁移链。针对历史空归属、字段缺失等既有数据验证编辑兼容性。

## 验收

页面与 CSV 对同一非法字段产生一致的拒绝结果，合法金额精确入库。验证原输入保留、非法存期和状态、日期格式、清空日期、CSV 部分合法、超限、写入失败回滚及旧权限测试。完成后在独立 MySQL 容器执行回归与真实 HTTP 检查。

设计与零金额规则已获用户确认，沿用当前会话执行和容器验证方式。
