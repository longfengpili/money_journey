# 单家庭资产归属与权限设计

## 已确认的业务规则

- 系统记录一个家庭，每个账号代表一个人，每位资产所有者都有账号。
- 全体已获准登录的成员查看全家资产，家庭汇总和储蓄规划使用全家数据。
- 普通成员只能新增、修改自己名下的资产。
- 家庭管理员可以代任何成员录入、修改资产，并调整归属。
- 暂时不登录的成员由管理员创建账号，使用不可用密码。
- 资产所有者关联账号，录入人单独记录，展示名称从所有者账号获取。
- 家庭管理员使用独立业务权限。

## 方案与选择

沿用 Django 单体，在现有账号、资金应用中集中权限规则。家庭管理员标记放在 UserProfile，资产仍通过 FundRecord.user 关联所有者。相比为单个家庭增加家庭与成员关系表，这个方案的迁移范围较小。相比继续依赖 is_superuser，独立业务角色能直接表达家庭权限。

## 实施提案

以下细节是本次实施建议。

- 增加 UserProfile.is_family_admin，默认 False，由系统维护账号在后台配置。角色本身不授予 Django 后台入口或账号权限管理能力。
- 系统超级管理员保留维护能力，家庭管理员在业务页面完成资产管理及成员账号创建。
- 使用 accounts.permissions 中的集中函数校验批准状态、家庭管理角色和记录所有权。is_staff 本身不产生家庭资产管理权限。
- FundRecord 增加可空 created_by 外键，记录新增和 CSV 导入的实际操作者。编辑和转移所有权不覆盖录入人，历史录入人未知时保持空值。
- FundRecord.user 是所有权依据。历史 owner 文本在兼容阶段保留，新记录同步用户名，页面和实时汇总按关联账号读取姓名及归属。
- 历史记录缺少 user 时，仅按唯一、完全匹配的用户名补齐关联。user 已有值但 owner 不一致时，以关联账号为权限依据，列入核对报告。无法确定归属的记录保持可见并标记待核对，由管理员显式指定所有者。
- 账号改名后，实时显示和汇总仍按账号主键归属。既有快照展示历史信息。
- 普通成员提交他人所有者时拒绝写入，空所有者默认本人。管理员编辑时省略所有者字段保留原归属，避免资产被无意转给编辑人。
- 管理员创建成员账号使用专用表单与页面，创建已批准账号并调用 set_unusable_password()，不能通过该入口设置管理员或系统权限。
- 审批页面允许家庭管理员操作，角色授予由系统维护账号负责。
- Django 后台资金编辑也使用同样的所有者限制，批量操作必须校验全部目标。账号管理页面的角色字段只对超级管理员开放。

## 交付与核验

关键证据来自权限函数测试、真实页面请求、CSV 上传、Django Admin 表单与批量操作，以及历史归属核对工具的只读运行。迁移增加字段并提供核对能力，真实历史数据的归属处理须以实际核对结果为依据。
