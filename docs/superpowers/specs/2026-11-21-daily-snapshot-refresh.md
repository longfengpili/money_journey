# 当天资金快照刷新与历史记录检查设计

## 目标与已确认规则

- 系统记录一个家庭，成员共享查看家庭资产。
- 用户已选择同一天再次创建快照时更新当天快照，反映最新资产。
- 本阶段在当前 D:/github/money_journey 目录执行，复用现有测试容器和独立数据库。

## 当前问题

- 当天只要存在任意一条快照就阻止生成，部分生成后无法继续。
- 按用户逐条写入缺少统一事务，中途失败会留下不完整的家庭快照。
- 并发请求缺少数据库唯一约束，可能产生重复的用户日快照。
- 每个用户分别进行多次金额、数量和维度查询，刷新过程中可能出现口径时点差异。
- 日期使用 timezone.now().date()，应按 Asia/Shanghai 本地日期确定业务日。
- 旧记录清理仅按创建时间硬删除，可能选中创建较早的 ACTIVE 资产。该任务目前没有加入 CRONJOBS。

## 推荐实现

沿用 FundSnapshot 的按成员分行结构，将完整家庭刷新集中到 funds.snapshots 的服务函数。按用户和业务日期唯一，一次事务读取、汇总并新增或更新当天全部成员快照。

## 业务规则提案

- 家庭管理员和系统维护账号可以刷新家庭快照，普通成员共享查看。
- 当天刷新采用完整家庭数据，以 ACTIVE 资产为统计范围，成员没有资产时记录零金额和零条数。
- 同一用户当天已有快照则更新原行，缺失则补齐。created_by 记录本次生成的管理员，updated_at 记录最近刷新时间，created_at 表示首次生成时间。
- 日期按 timezone.localdate() 获取，历史日期的快照继续用于趋势展示。
- 全部成员的刷新统一提交，任何写入失败均整体回滚，原有当天快照保持完整。
- 并发刷新按固定顺序锁定成员，并结合用户与日期唯一约束，防止重复行和部分提交。
- 金额计算使用 Decimal，银行和类别汇总以两位小数字符串保存，旧 JSON 数值记录继续正常读取。图表使用已有 total_amount 字段。
- ACTIVE 资产缺少所属账号时明确提示核对归属，避免家庭快照遗漏金额。

## 历史兼容

- 新增只读快照核对命令，报告同用户同日期重复行、未关联账号的旧快照和 ACTIVE 空归属资产。
- 唯一约束迁移前检查已有重复数据，输出明确定位和处理提示。历史修复依实际核对结果决定。
- 当天存在未关联账号的旧快照时，刷新前提示核对，避免与新成员快照合并后重复累计。
- 旧快照的所有者文本继续表达历史名称，新增和当天刷新使用当前账号信息。
- 后台的快照金额和维度汇总使用计算生成结果，后台入口按家庭管理权限限制写入。

## 旧记录处理提案

本阶段将 clean_old_records 改为只读检查，报告三年前最后更新、状态为 WITHDRAWN 或 ROLLED_OVER 的候选记录。ACTIVE 记录始终排除在候选范围外。

历史记录保留在原表，待后续明确保留周期、归档方式和查询需求后实施归档流程。本阶段的定时配置继续执行到期提醒。

## 验收

1. 当天新增、编辑、转移归属或修改状态后，管理员刷新能得到最新且一致的成员汇总。
2. 重复点击保持同一组用户日记录，补齐历史缺失成员。
3. 中途写入失败整体回滚，并发调用最终没有重复用户日记录。
4. 普通成员刷新请求被拒绝，查看共享数据正常。
5. 精确金额、零资产成员、本地日期边界和旧快照读取有回归覆盖。
6. 旧记录检查运行前后数据库记录数量及内容一致。
7. 在独立 MySQL 测试库和真实 HTTP 流程中复核，并记录迁移及兼容性证据。
