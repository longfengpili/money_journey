## 页面方案

桌面使用左侧固定导航、右侧内容；移动端导航折叠为菜单，内容单列。

| 页面 | 内容与操作 |
| --- | --- |
| 总览 | 页标题与所有者/银行/类别/状态筛选，4 个指标卡，趋势，银行和类别分布，成员汇总 |
| 资产 | 筛选与新增入口，资产表格（手机记录卡），分页，弹窗编辑，归属和状态清楚展示 |
| 导入与快照 | CSV 模板与上传，逐行错误及成功数；管理员刷新快照，显示本次新增和更新数 |
| 计算器 | 基本参数卡，动态年龄段，计算按钮，结果摘要与图表，月份明细和 CSV 导出 |
| 成员 | 待批准成员、审批按钮、创建不可登录成员；普通成员无管理入口 |
| 登录/注册 | 一致的表单组件、字段错误、待批准与停用提示 |

## API 契约与实现选择

- 前端 /app/，JSON /api/v1/，维护后台 /admin/，旧页面原路由保留。最终根入口跳转 /app/，可通过设置回退旧首页。
- Session+CSRF 同域认证；初始化返回 masked token，登录后更新 token；登录匿名请求也有 CSRF 校验。API 每次检查当前审批和停用状态。
- JSON 金额使用字符串，后端 Decimal；前端字符串格式化，只有图表转 number。列表包含 count、page、page_size、results；默认 50，上限 100。
- 错误包含 code、message、fields；403 的 AUTH_REQUIRED 与 FORBIDDEN 区分；系统失败不暴露内部异常。
- 新所有者选择使用 user_id，历史文本使用独立 owner 查询兼容；NULL 归属明确待核对。
- 资产 API 使用 FundRecordForm 适配 JSON，PATCH 以旧值补齐未传字段；行锁后校验归属和保存。明确拒绝客户端赋值 created_by、can_edit 和管理员角色。
- CSV 与快照直接调用现有模块；写请求失败不自动重试。
- 计算沿用原规则，不在 UI 迁移中改变年龄段重叠语义。出生年份上限改为本地当前年，年龄段起止校验共同使用表单；其他新业务规则列后续事项。
- 计算结果使用新的会话键，避免与旧模板浮点结果互相破坏；退出及账号切换清理结果，刷新可恢复。
- 前端不持久化敏感业务缓存，身份变化后卸载业务页面；异步读取取消或忽略过期响应，写成功触发重读。
- 图表继续 Chart.js，BoardUI 提供免费基础样式和控件；页面布局与业务组件由项目维护。
